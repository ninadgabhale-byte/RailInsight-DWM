Data Warehouse

Star-schema design, DDL scripts, indexing, sample analytical queries and Star vs Snowflake comparison.

Star schema

One central fact table surrounded by denormalised dimension tables. Every dimension is a single table joined directly to the fact table.

  • Fewer joins → faster, simpler OLAP queries
  • Some redundancy (e.g. station name repeated for every station in a city)
  • Easy for BI tools and for explaining in a viva
Snowflake schema

The same dimensions are normalised into sub-dimension tables, so the diagram branches out like a snowflake.

  • Less redundancy and less storage
  • More joins → slower, more complex queries
  • Easier to maintain when hierarchy attributes change

Why we chose Star: the data set is read-heavy (analytics), the dimensions are small, and fewer joins make OLAP queries on ~700K fact rows faster.
